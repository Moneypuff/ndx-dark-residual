# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A no-API-key, free-data-only quant research pipeline that builds a family of self-contained
static HTML dashboards (published to GitHub Pages) plus a set of one-off research studies
whose findings feed the dashboards' text and thresholds. There is no server, no database,
and no JS build step: every page is a single `.html` file with data baked in as an embedded
JSON payload, generated by a Python "build" script from a static HTML "template".

Core data sources (all free, no auth): FINRA daily consolidated short-volume files
(`CNMSshvol*.txt`), Yahoo Finance daily bars and option chains, iShares ETF holdings CSVs,
SEC EDGAR filings, Cboe COR1M/DSPX CSVs, and (optional, keyed via `GEXPLUS_KEY`)
SqueezeMetrics' GEX+ feed with a free-CSV fallback when no key is set.

## Commands

```bash
# Install
pip install -r requirements-dev.txt      # runtime + test deps (adds pytest, scipy as an oracle)
pip install -r requirements.txt          # runtime only (numpy, pandas, requests, openpyxl)

# Test (pytest.ini points testpaths at tests/, quiet mode by default)
python -m pytest                         # full suite
python -m pytest tests/test_stats.py     # one file
python -m pytest tests/test_stats.py::test_gammaln_known_values   # one test
python -m pytest -k betainc              # by keyword

# Build a page locally (writes into docs/, which is gitignored except .nojekyll)
python ndx_dark_residual.py --demo --out demo.html          # synthetic data, no network
python ndx_dark_residual.py --dark-start 2018-08-01 --out docs/index.html
python build_comovement.py --docs-out docs/comovement.html --cache-dir .ndx_dark_cache
python build_gex_dispersion.py --docs-out docs/gex_dispersion.html --cache-dir .ndx_dark_cache
python build_regime_log.py --barometer docs/gex_dispersion.html --docs-out docs/regime_log.html --cache-dir .ndx_dark_cache
python build_vol_tracker.py --snap-dir optsnap --docs-out docs/vol_tracker.html --cache-dir .ndx_dark_cache
python build_vol_surface.py --snap-dir optsnap --docs-out docs/vol_surface.html
python build_report.py --cache-dir .ndx_dark_cache --docs-out docs/earnings.html

# Capture leg (only unrepeatable dataset -- Yahoo keeps no option-chain history)
python snapshot_option_chains.py --out optsnap
```

Almost every build/study script takes `--cache-dir` (default `~/.ndx_dark_cache`) and
`--refresh` (force re-fetch instead of trusting the on-disk cache); check each script's
own `--help` / module docstring for its specific flags before assuming one applies.

There is no lint config in the repo (no ruff/flake8/black config file) -- match the
surrounding style rather than reformatting wholesale.

## Architecture

**`ndx_dark_residual.py`** is the foundation module every other script imports
(`import ndx_dark_residual as N`), not just the main dashboard's entry point. It owns:
- the FINRA fetch/parse/cache layer and the DPI/"D" construction (`compute_dollar_dix` etc.),
- the Yahoo daily-bar fetch/cache layer (raw close for dollar weighting, adjusted close for
  split-safe returns),
- the NDX-100 constituent/weight table (`NDX100_WEIGHTS` -- hand-maintained, dated, needs
  periodic refresh from source as membership/weights drift),
- shared helpers (`load_watchlist`, `compute_forward_return`, disk caching primitives) reused
  by nearly every other script in the repo.

Downstream scripts split into two families that both build on that foundation:

1. **Dashboard/page builders** (`build_*.py`, `snapshot_option_chains.py`) -- each pairs with
   a `*_template.html` file and produces one page under `docs/`. The pattern, consistent
   across all of them:
   - the template is static HTML/CSS/JS with `/*__NAME__*/` placeholder comments,
   - the build script computes a payload dict, serializes it with
     `json.dumps(x, separators=(",", ":"))`, and does a literal `.replace()` into the
     template text,
   - large payloads (the main dashboard, comovement) are deflate-compressed + base64-encoded
     (`zlib.compress` + `base64.b64encode`) and inflated client-side via the native
     `DecompressionStream('deflate')` -- keeps a single-file page under GitHub's practical
     size limits while staying dependency-free and `file://`-safe,
   - all financial math happens in Python at build time; the browser only renders
     pre-computed numbers (see `build_vol_surface.py`'s "no financial math happens in JS").
   - builders commonly import from each other, not just from `ndx_dark_residual`: e.g.
     `build_vol_surface.py` imports `atm_iv`/`load_snapshots` from `build_vol_tracker.py`,
     `build_regime_log.py` reads the already-built `gex_dispersion.html` payload back in,
     `build_comovement.py` reads the payload out of `docs/index.html`. Check a script's
     docstring for which upstream page(s) it must be built after.

2. **Research studies** (`*_study.py`, top-level, not under `tests/`) -- standalone analyses
   answering a specific question, each writing a corresponding `*_FINDINGS.md` /
   `*_PLAYBOOK.md` / `*_GUIDE.md` doc at the repo root. These are not part of the nightly
   build; they're run ad hoc and their conclusions get hand-transcribed into the docs (and
   sometimes into thresholds hardcoded in a builder, e.g. `build_regime_log.py`'s bucket
   stats). Several studies import detector functions back out of a builder module rather than
   duplicating them (e.g. `gdx_chase_study.py` and `etf_path_study.py` both import
   `conviction_frame`/`detect_breaks`/`spread_frames` from `build_regime_log.py`).

`trade_structures.py` is a pure, unit-tested module (structure suggestion + smile-marked
option pricing) used by the vol tracker/surface builders; it has no CLI of its own.

**Statistics are hand-rolled, not scipy-based**, in production code (`_gammaln`, `_betainc`,
`_t_sf`, `_pearson`, `_spearman`, `_welch` in `earnings_dpi_study.py`) so the pipeline that
runs in CI has no scipy dependency. `scipy` is listed only in `requirements-dev.txt`, used
exclusively as a trusted oracle in tests to validate those reimplementations
(`tests/test_stats.py`) -- do not add a scipy import to any non-test module.

**No look-ahead is a first-class design constraint**, not an afterthought: several
studies compute both a full-sample basis and an "expanding-window" (real-time-safe) basis
for percentiles/deciles, and the dashboard has a "trailing deciles (no look-ahead)" toggle
for the same reason. When adding a new signal/backtest, follow this precedent -- prefer
expanding/trailing windows for anything presented as knowable "as of" a given day.

**Caching**: on-disk cache under `--cache-dir` (default `~/.ndx_dark_cache`, gitignored) is
shared across almost all scripts -- FINRA day-files and Yahoo bars accumulate incrementally
and same-day reruns are cheap. `snapshot_option_chains.py` writes to a *different*, unrelated
store: one compressed CSV per trading day under `optsnap/`, which lives on the orphan
`optsnap-data` branch (not `main`) because it's the one dataset that can't be rebuilt after
the fact -- Yahoo exposes no option-chain history. The Pages build workflow checks that
branch's `optsnap/` directory into the working tree before running the vol tracker/surface
builders. `scripts/shrink_history.sh` documents the (manual, force-push) precedent for
squashing that branch's history if it grows large.

## CI / deployment (`.github/workflows/`)

- **`tests.yml`** -- runs `python -m pytest` on every push/PR. No deploy side effects.
- **`refresh.yml`** -- the nightly full build. Runs tests as a gate, builds every dashboard
  page into `docs/`, and deploys `docs/` as a GitHub Pages *artifact* (never a git commit --
  `contents: read` only). Scheduled at 10:00pm ET; duplicated cron entries exist because
  GitHub Actions cron is fixed-UTC and can't follow US DST, so a `gate` job picks the one
  that actually landed at 22:00 ET and skips the other.
- **`gex_catchup.yml`** -- hourly 11pm-6am ET retry that rebuilds *only*
  `gex_dispersion.html` + `regime_log.html` (fetching every other already-live page verbatim
  from Pages instead of rebuilding it) when SqueezeMetrics' feed publishes late. Shares the
  `pages` concurrency group with `refresh.yml` so the two never deploy at once.
- **`optsnap.yml`** -- the daily option-chain capture. This is the one workflow with
  `contents: write`, and it pushes *only* to `optsnap-data`, never to `main`.

When editing any workflow, preserve the ET-vs-UTC dual-cron + gate pattern and the shared
`pages` concurrency group -- both exist to work around specific bugs described in the
workflow file comments (DST-blind cron, deploy races), not incidental style choices.

## Testing conventions

- Tests live in `tests/`, one `test_<module>.py` per module under test; `conftest.py` just
  puts the repo root on `sys.path` so `import <module>` works regardless of invocation dir.
- Prefer validating hand-rolled numeric code against scipy/numpy as an oracle
  (`pytest.approx`) over hand-computing expected values, matching the existing pattern in
  `tests/test_stats.py`.
- Network-touching code paths should be tested through cached/mocked/synthetic inputs (see
  `--demo` mode in `ndx_dark_residual.py`) so the suite stays fast and offline -- CI has no
  external credentials and several data sources (Yahoo option chains, GEX+) are flaky or
  gated by design.
